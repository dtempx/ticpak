# AGENTS.md

This file provides guidance to AI coding agents working with code in this repository.

## What this is

ticpak packages a multi-file TIC-80 Lua project (`main.lua` + modules loaded with `require`) into one uploadable `.tic`: it inlines modules as `package.preload` entries, optionally minifies, boots the bundle headless in TIC-80 Pro, saves the `.tic`, and checks it against TIC-80's limits. README.md is the full user reference; keep it in sync when behaviour or options change. `skills/ticpak/` is an Agent Skill for ticpak's *users'* agents (`SKILL.md` routes to `references/init.md`, `bundle.md`, `check.md`); it restates CLI flags, error messages and limits, so update it too when those change.

## Commands

```
pip install -e ".[prompts,test]"     # editable install; `test` adds lupa (real Lua 5.3)
python -m ticpak                      # run from a clone without installing

python tests/options/test_options.py              # every minify-option combination (~20 s)
python tests/options/test_options.py -k Behaviour # one test class (stdlib unittest)
TICPAK_BOOT=1 python tests/options/test_options.py -k Boot   # boots each in TIC-80, compares .tic assets (~12 min)
python tests/minify/run.py [fold|bytecode|fixtures]          # minifier suites
python tests/minify/difftest.py path/to/game/tic80            # frame-by-frame diff on a real port
python tests/minify/difftest.py --all                         # every <game>/tic80 under $TICPAK_GAMES
python tests/error/test_error.py                              # ticpak error on real Lua 5.3 errors (~1 s)

python tests/options/make_samples.py   # regenerate samples/ and project/main.lua after editing tests/options/code/
python scripts/update_reserved.py      # refresh minify.py's TIC-80 reserved-name and library-key block from the binary
```

There is no linter or pytest config; tests are plain scripts using stdlib `unittest`. Behaviour tests skip without `lupa`. Anything that boots TIC-80 needs the **Pro** binary, found via `$TIC80`, then `tools/tic80.exe` / `tools/tic80/build/bin/tic80` in the nearest ancestor folder, then `tic80` on PATH.

## Constraints

- Python 3.9+ and **no runtime dependencies** (questionary is an optional extra; `console.py` falls back to plain numbered prompts). Don't add required deps.
- Target Lua is TIC-80 1.2's embedded **Lua 5.3** (no `<const>`); every minifier semantic rule is Lua 5.3's.
- `bundle`, `check` and `error` must never prompt (`error` reads the error text from stdin when `-e` is not given, which is input, not a question); only the bare `ticpak` command is interactive, and it exits with status 2 when there is no terminal.

## Before committing

Whenever you make a change, bump the version as part of it unless the uncommitted changes already bump it (check `git diff HEAD -- pyproject.toml ticpak/__init__.py`). Bump `version` in `pyproject.toml` and `__version__` in `ticpak/__init__.py` together and keep them equal: users install from git, so the version is how they, and bug reports, tell builds apart, and `ticpak --version` prints the one in `__init__.py`.

## Architecture

`cli.py` is only the front end (argparse, interactive questions, dispatch). The pipeline:

1. `bundle.py` — `find_cart` → `Target`, which turns `-o` into the outputs to keep (`out_kind`: none → `<name>.tic` beside `main.lua`; `X.tic` → that file only; `X.lua` → the bundle only; a folder → `<name>.lua`/`.tic`/`.txt` plus the decode maps; anything not kept is `None`). `is_cart` tells a cart (`main.lua`, or a header of two tags or more, or asset sections running to the end of the file) from a module on its own (`cli.minify_command`, `ticpak minify`, uses it too: only a cart that requires nothing is minified whole-program), which `minify_module` minifies as a fragment to `<module>.min.lua`. `freshness` (timestamp-only up-to-date check), `assemble` (header + stub + one `package.preload["mod"] = function(...) ... end` per required module; asset chunks set aside; `origin` maps each bundle line to `file:line`), then `minify.minify_cart_ex`, then `add_stamp` (the `-- ticpak: VERSION -m...` line after the header tags, added after minifying since the minifier would strip it; the decode map's output lines shift past it). Those three steps are `build()`, which writes nothing and returns a `Built`; `bundle()` writes its outputs, and `ticpak error` calls `build()` alone to remake a decode map in memory. `map_doc(Built)` is the decode map (`.minify.json` format 2: `lines`, `segments`, `renames` with `uses`, the `build` stamp and a `code` hash); up to `comments` it pairs the code's tokens with the unminified bundle's, since only comments and whitespace changed. `built_options` reads that line back from an existing `.tic`/`.lua`, for the force-rebuild hint's `-m` and the note when `-m` changed; the summary's `minify:` comes from it too. The bundle text goes to `t.code`, and to disk only for a folder build (then the `.minify.txt`/`.minify.json` decode maps for any option past `comments`) or, once it boots, for `-o X.lua` (`save_bundle`). Also guards against unminified comment lines starting `-- <`, which TIC-80 reads as the start of asset sections, and stops on an asset section in a module (minified, it would be stripped silently): only `main.lua`'s sections are packaged.
2. `run.py` — finds TIC-80 Pro, writes `t.code` into an isolated temp folder, boots it headless, saves the `.tic` (to `t.tic`, or a temp path for a `.lua`-only build's check).
3. `report.py` + `check.py` — parse the `.tic` chunks, check code budget/banks/cover/header, print the summary (the minify savings only as `--verbose` detail), and with `-r` write the full report to `t.txt` (`<name>.bundle.txt` beside the output, or `-r PATH`; `Target` resolves it). `check.py` also serves `ticpak check FILE...`. `-q` swaps `sys.stdout` for devnull in `cli.main`, so nothing needs its own quiet switch; that includes `console.Progress`, the build's gray progress bar, which draws on the stream behind `sys.stdout` only when it is a real console. The pipeline moves it with `console.step(key, message, seconds)` (a no-op when no bar is showing), and `FlatStdout` erases and redraws it around each printed line.
4. `header.py` — metadata tags, output name (`saveid` → `title` → slug), filling in missing tags.
5. `errors.py` — `ticpak error`. `find_map` picks the decode map for the cart `built_target`/`-o` finds: its folder build's `.minify.json` when the `code` hash matches the cart's code, else `build()` with the cart's stamped `-m` and `map_doc`, checked against the cart (a mismatch is a `WARN`, not a stop). `decode` parses the error text (Lua 5.3's message and `luaL_traceback` frames; only `[string "..."]` chunks named after the cart's first line, unless none is) and resolves each location by the name it quotes: `Decoder.find` locates the short name's columns on the output line (filtered by what the message says it was doing: indexed, called, ...), the segments map them to a source line, and a variable's `uses` pick which binding a reused short name was. A frame's line is found by its call to the frame above it; a message that names nothing borrows the frame below it.

### The minifier (`minify.py`, ~4k lines, also `ticpak minify`)

Self-contained: lexer → AST parser → tree passes → emitter → layout. Key ideas that span the file:

- User-facing **options** (`OPTIONS`: comments, rename-vars, rename-functions, rename-tables, constants, whitespace, extra) map to internal **passes** (`ALL_PASSES`: fold, inline, dce, shake, rename-vars, rename-functions, rename-tables, sugar, alias, literals, merge) via `OPTION_PASSES`; `whitespace` controls reflow, not a pass. Every option implies `comments`. Two **presets** (`PRESETS`): `default` (`DEFAULT_OPTIONS`, every option but the opt-in `rename-functions` and `rename-tables`: a bare `-m`, `ticpak minify` with no flags, the interactive default) and `max` (`ALL_OPTIONS`: `-m=max`, `ticpak minify --max`, the API's default `mode`). `parse_options` and `-m` accept presets alongside options; the build stamp records `-m` / `-m=max` / `-m=a,b`, and `bundle.flag_options` reads an older build's `rename` as `rename-vars`.
- `minify_ex` short-circuits: no options → passthrough; `comments` only → `strip_comments` with a token-stream equality check; otherwise `minify_max`, which iterates fold/inline/dce/shake to a fixpoint, then `pass_keys` (rename-tables), then sugar/alias/literals/merge, then one `pass_rename` for rename-vars and rename-functions, then layout. `alias` and `literals` add one top-level `local` each (sharing a cap of 180 top-level locals) and walk the tree with `slot_walk`, which hands each expression a setter to replace it.
- Safety nets are deliberate: output is re-lexed and must equal the emitted tokens, re-parsed, and must not contain a `-- <X` line. Failing these raises `AssertionError` rather than emitting. Keep them.
- **Whole-program mode** (default) may inline/remove/rename globals because the bundle is the whole program; `whole_program=False` (fragment) never touches globals. Names that TIC-80 or Lua define are never renamed: `TIC80_GLOBALS` (globals) and `TIC80_LIBRARY` (the library tables' keys, for rename-tables) are an embedded generated block between `# <reserved>` markers (regenerate with `scripts/update_reserved.py`, don't hand-edit), plus `CALLBACKS`, `EXTRA_RESERVED` and `EXTRA_LIBRARY_KEYS`.
- **rename-tables** (`pass_keys`, spec R13/D14) renames table keys by spelling: every occurrence of a key name, on any table, gets the same new name, so the program's own key handling lines up by construction. Its safety comes from `_KeyFlow`, a flow-insensitive whole-program analysis solved to a fixpoint: shapes are sets of alternatives (`("lit", s)`, `("re", pattern)`, `("len", n)`, `ANY`, `NONID`, `KEY` for keys handed back by `pairs`/`next`/`__index`, `("fn", id)` per function expression, `("tbl", id)` per table constructor, `("lib", name)`, `FNQ`/`TBLQ` for untracked values). Table slots are per constructor and per key name, with metatables (`__index`/`__newindex`) followed. Sets only grow, so a transfer function must never answer "anything" for lack of information yet (a concatenation piece with no strings is a number's text, not `.*`). After solving, `_pass_keys` checks every computed key (`ANY` → off; lit/pattern/length → those names kept), every place a `KEY` would show (concat, `#`, order, string functions, `print`/`trace`, … → off), `gsub` with a table, dynamic access, fragment mode and NOMINIFY-protected code (→ off; `report.keys_off` says why, with the line). Key literals become fields (the `Index` node's class becomes `Field`). Renames go to the decode map as kind `field`.
- Each function starts on its own line, so runtime errors stay decodable. After layout, `_out_positions` places every token in the output text (`(line, column)` by parse position, and each lexed token's source line), which gives `Result.segments` (`line_segments`) and `Result.uses` (each rename's first and last use, beside `renames`; `report.rename_pos` holds them as parse positions until then). `minify_cart_ex` and `bundle.build` shift both like `line_map`. Function names are renamed only with `rename-functions` (`Info(rename_functions=True)` marks function bindings `renamable`; `can_rename` is the same test without the function exclusion, for the savings breakdown); otherwise they keep their names so tracebacks read as written. A NOMINIFY on a `function`/`local function` statement pins its name too.
- `savings=True` (off by default) also measures what each option saved, by source line (`Savings`; every token carries its source line through the passes). It only measures and nothing reads it back. With `constants` and `extra` both on, `_max_savings` reruns the fixpoint loop with `inline` alone (`fixpoint_only`) to split them; `pass_rename` returns the bytes function names saved per line, which splits `rename-functions` from `rename-vars`. `bundle.py` groups it per file through `origin` into `t.savings`; `report.savings_table` shows it as `--verbose` detail and in the `-r` report, never in the default output.
- `NOMINIFY` directives (a comment block, or a comment after code) attach to statements: they keep variables (pinned), functions, modules, the whole cart, or else their own comment. `directives()` resolves them against one parse; `protect` turns protected bodies into verbatim `raw` tokens and inserts kept comments as `comment` tokens (`Comment` statements / table fields).

`docs/minify-spec.md` is the contract, with requirement IDs (e.g. D7, R10c) that code and tests cite; `docs/minify.md` is usage. Update the spec when changing minifier semantics.

### Tests

- `tests/options/` runs original and minified sample carts under real Lua 5.3 against a logging stub of the TIC-80 API (`harness.lua`) and requires identical call logs. Samples rely on marker names (`renameme_*`, `renamefn_*`, `renamekey_*`, `keepkey_*`, `keepme_*`, `pinned_*`, `keepfn_*`, `keepmod_*`, `CONST_*`, `unused_helper_fn`, ...) described in `tests/options/README.md`; `samples/` and `project/main.lua` are generated. `TestRenameTables` covers rename-tables on small programs.
- `tests/minify/run.py` fuzzes constant folding against Lua, checks bytecode equality for variable-rename-only output, and runs `fixtures.lua` under `max`; a fixture named `table keys: ...` must have rename-tables renaming, or off when its name ends `(pass off)` (those cases each leak a key's spelling some way, so an unsound analysis fails them). `difftest.py` compares real games frame by frame under the `max` preset (so `rename-functions` and `rename-tables` too); its order-stable `pairs` sorts renamed keys by their original names from the decode map.
- `tests/error/` gives small projects (`CASES`) one bug each and raises each error twice under real Lua 5.3: from the sources as written (each file its own chunk, `enemies.lua:13:`) and from the bundle loaded as TIC-80 loads it (`[string "-- title: ..."]:11:`, `debug.traceback` standing in for TIC-80's `luaL_traceback` handler). `ticpak error`'s decoding must turn the second into the first under every preset; a frame may decode to a range holding the right line (one bundle line calling the same function twice), the message line never. It also checks the map format on the option samples and the `ticpak error` command (map file vs rebuild, changed sources, no cart, no location).
